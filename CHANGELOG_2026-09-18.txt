5. SINKRONISASI getdata/api_hanif* KE QUENBY & GRASINET
------------------------------------------------------------
Airlink punya versi lebih matang untuk sinkronisasi ke sistem Keuangan:
- Transaksi 'kompensasi_free' dikecualikan dari sinkronisasi pendapatan
- Baseline SYNC_TRANSACTION_START_ID supaya histori lama tidak ikut
  ter-backfill massal saat pertama kali jalan
- Pemetaan bank lebih akurat (pakai data mapping asli dari API Keuangan,
  bukan tebak kata kunci)
- Tracking status sync per-pelanggan (kolom KEUANGAN_SYNC_STATUS/ERROR)
Fitur-fitur ini dibawa ke quenby DAN grasinet (getdata/api_hanif_cron_
pelanggan.php, api_hanif_cron_transaksi.php), dengan URL endpoint Keuangan
masing-masing TETAP dipertahankan (quenby & grasinet share endpoint
"sistem-manajemen-keuangan" yang sama -- keduanya TIDAK ditimpa URL
airlink yang endpoint-nya terpisah "/airlink/").

Catatan: quenby & grasinet kini identik byte-per-byte untuk kedua file ini
(dikonfirmasi via diff).

Ditemukan & diperbaiki sekalian:
- 2 kolom (KEUANGAN_SYNC_STATUS, KEUANGAN_SYNC_ERROR) dipakai di query
  UPDATE tapi TIDAK punya self-heal ensureColumnExists() -- akan
  menyebabkan error "Unknown column" di server manapun yang belum punya
  kolom itu secara manual. Ditambahkan self-heal-nya (di quenby, grasinet,
  DAN airlink). Kolom langsung dibuat (bukan menunggu cron jalan) di
  quenby & grasinet -- di grasinet SEMUA 10 kolom KEUANGAN_* memang belum
  ada sama sekali sebelumnya (belum pernah pakai versi cron ini), semua
  berhasil dibuat.
- File baseline getdata/keuangan_transaction_start_id.txt dibuat:
  - quenby   : isi 91465 (MAX id transaksi saat migrasi dijalankan)
  - grasinet : isi 234406 (MAX id transaksi saat migrasi dijalankan)
  Supaya histori transaksi lama tidak ikut ter-backfill massal saat cron
  pertama kali jalan di kedua server ini.
- SATU baris di getdata/api_hanif.php TIDAK disamakan dengan airlink,
  malah SEBALIKNYA: airlink diperbaiki mengikuti pola quenby (grasinet
  sudah otomatis aman -- filenya sudah identik dengan quenby sejak awal,
  tidak perlu diubah). Query dropdown Server untuk akun ASSISTANT di
  airlink pakai "WHERE AREA IN (...)" -- pola ini berisiko BOCOR DATA
  lintas-brand
  kalau 2 server beda tenant kebetulan punya nama AREA yang sama (bug
  class yang sama seperti sudah diperbaiki di file lain sebelumnya).
  Diganti ke "WHERE id IN (...)" (aman, id = primary key unik) di airlink.

8. FITUR BARU: "BUAT TAGIHAN SEKARANG" DI PORTAL PELANGGAN (2026-09-19)
----------------------------------------------------------------------------
Sebelumnya kalau belum ada tagihan aktif utk periode berjalan, portal
pelanggan (broadband/portal_bayar.php) cuma menampilkan teks statis "Belum
ada tagihan baru.." tanpa ada cara bagi pelanggan utk memicu pembuatannya
sendiri.

Ditambahkan file baru broadband/proses_buat_tagihan_sendiri.php + tombol
"Buat Tagihan Sekarang" di titik itu. Mekanismenya SAMA PERSIS dengan
"Manual Generate Invoice" milik admin di menu Transaksi Billing (insert
baris STATUS='PENAGIHAN', pengecekan anti-duplikat per periode), bedanya:
- Cuma utk 1 pelanggan yang sedang login (bukan generate massal).
- Periode DIHITUNG OTOMATIS oleh sistem lewat variabel yang sudah ada di
  cek_sesi.php ($isFixedDueDateTampilFokus, $periodeBerjalanTampilFokus /
  $bulanAktualTampilFokus, $adaPenagihanTampil -- logika TIPE_TEMPO-aware
  yang SAMA PERSIS dgn yang menentukan status SHOW/HIDE tagihan). TIDAK
  ADA input periode dari pelanggan sama sekali -- supaya tidak bisa
  disalahgunakan (pilih periode jauh ke depan / bikin tagihan dobel).
- Paket gratis/Rp0 TIDAK menampilkan tombol ini (diminta -- paket seperti
  itu memang tidak perlu ditagih).
